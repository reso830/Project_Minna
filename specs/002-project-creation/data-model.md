# Data Model: Project Creation

This document defines the schema, database tables, local configurations, and validation rules for Feature 002 - Project Creation.

## Global Project Database Registry

In compliance with **Constitution Principle III and VI**, raw flat files are rejected as the source of truth for runtime project states. The central project registry is a local SQLite database stored at:
`~/.minna/projects.db` (`C:/Users/acres/.minna/projects.db` on Windows).

A flat file projection is exported to `~/.minna/projects.json` for external inspections on mutation, but this JSON file is read-only and never parsed by the application as the source of truth.

### Database Schema

#### 1. `events` Table (Append-Only Journal)
Tracks all registration and project open actions.

```sql
CREATE TABLE IF NOT EXISTS events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp TEXT NOT NULL,          -- ISO 8601 UTC timestamp string
  actor TEXT NOT NULL,              -- "human" | "system"
  type TEXT NOT NULL,               -- "project.registered" | "project.opened"
  payload TEXT NOT NULL             -- JSON string containing project metadata
);

-- Write-protection trigger on events
CREATE TRIGGER IF NOT EXISTS prevent_registry_event_update
BEFORE UPDATE ON events
BEGIN
  SELECT RAISE(ROLLBACK, 'Updates are not allowed on the append-only registry events table.');
END;

CREATE TRIGGER IF NOT EXISTS prevent_registry_event_delete
BEFORE DELETE ON events
BEGIN
  SELECT RAISE(ROLLBACK, 'Deletions are not allowed on the append-only registry events table.');
END;
```

#### 2. `projects` Table (Current State Projection)
Calculated current state projection updated in the same transaction as the event write.

```sql
CREATE TABLE IF NOT EXISTS projects (
  id TEXT PRIMARY KEY,              -- Unique slug identifier (lowercased)
  name TEXT NOT NULL,               -- Display name (preserves exact folder casing)
  path TEXT UNIQUE NOT NULL,        -- Absolute unique directory path
  last_opened_at TEXT NOT NULL      -- ISO 8601 UTC timestamp
);
```

### TypeScript Typings

```typescript
export interface ProjectRegistryEntry {
  id: string;             // Unique slug identifier, e.g. "project-celia"
  name: string;           // Display name preserving casing, e.g. "Project_Celia"
  path: string;           // Absolute filesystem path to the project root
  last_opened_at: string; // ISO 8601 UTC timestamp
  available?: boolean;    // Runtime boolean derived by checking path resolution on disk
}

export type ProjectRegistry = ProjectRegistryEntry[];
```

### Validation Rules
1. **Uniqueness**: The `path` field must be unique. No two entries in the registry can share the same absolute path.
2. **Casing**: The `name` must preserve the exact casing of the folder on disk.
3. **ID Generation**: The `id` is generated by slugifying and lowercasing the `name` (converting non-alphanumeric characters to `-`, stripping leading/trailing dashes, lowercasing).
4. **Collision Handling**: If the generated slug matches an existing entry's `id` but has a different `path`:
   - Append a numeric suffix starting from `-2` (e.g. `slug-2`, `slug-3`) until a unique `id` is resolved.
5. **Ordering**: The `projects` projection list is returned in descending order of `last_opened_at`.
6. **Concurrent Transactions**: All writes use `BEGIN IMMEDIATE TRANSACTION` to lock the SQLite database, preventing concurrent write conflicts and lost updates.

## Local Project Configuration & Metadata

Each Minna project directory maintains:
1. **Local event journal (`.minna/minna.db`)**: Authoritative SQLite database for local project events, work items, and runtime states (scaffolded using [db.ts](file:///D:/Alvin/_CodeProjects/Project_Minna/src/core/db.ts) on initialization).
2. **Local config file (`.minna/config.yaml`)**: Reserved strictly for static, version-controlled metadata.

### config.yaml Structure

Fresh scaffold (no prior `.minna/` or `minna.project.yaml` — Case A):

```yaml
version: 1
created_at: <ISO 8601 UTC timestamp>
description: null
```

Migrated from legacy `minna.project.yaml` only:

```yaml
version: 1
created_at: <ISO 8601 UTC timestamp>
description: null
speckit_dir: ".specify"
github: null
default_branch: "main"
```

### Properties Definition
- **`version`** (Required): An integer specifying the project schema version. Defaults to `1`.
- **`created_at`** (Required): An ISO 8601 UTC timestamp capturing when this project was first initialized/scaffolded. Must not be modified on subsequent openings.
- **`description`** (Optional): A string describing the project or `null`. Defaults to `null`.
- **`speckit_dir`** (Migration-only): A string specifying the specifications directory path relative to project root, carried over from `minna.project.yaml`. Never written on a fresh scaffold.
- **`github`** (Migration-only): A string or `null` specifying the remote GitHub repository label, carried over from `minna.project.yaml`. Never written on a fresh scaffold.
- **`default_branch`** (Migration-only): A string specifying the default git branch, carried over from `minna.project.yaml`. Never written on a fresh scaffold.

### Validation Rules
1. **File Location**: Must exist exactly at `.minna/config.yaml`.
2. **Key Check**: The file must parse as valid YAML and contain both `version` and `created_at`.
3. **Immutability**: `created_at` is set once during scaffolding and must not be overwritten or updated.
4. **Never Auto-Repair**: If a `.minna/` directory already exists but `config.yaml` is missing or invalid, Minna rejects the project and raises a validation error. It will not attempt to overwrite or automatically repair the file to prevent data loss. Auto-scaffolding of `.minna/config.yaml` and `.minna/minna.db` only runs when the `.minna/` directory itself is entirely absent.
5. **Database Initialization**: Scaffolding initializes the SQLite schema inside `.minna/minna.db` dynamically. If `.minna/config.yaml` exists but `.minna/minna.db` is missing, it is lazily created and initialized upon first project open.
6. **Scope of migration-only fields**: `speckit_dir`, `github`, and `default_branch` are written **only** when converting a pre-existing `minna.project.yaml` (see plan.md's Configuration Migration & Backward Compatibility section). A fresh scaffold (Case A) never writes these keys — introducing Git-related defaults on a brand-new project would exceed this feature's scope, which explicitly excludes Git integration.
